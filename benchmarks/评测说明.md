# EvoWeave_deepseek 评测说明

> 本文档登记实验协议、成本与复现规则（对应实验方案.md 第 12 节交付物）。

## 1. 实验对象与范围

- 被测系统：EvoWeave_deepseek（演进织网·DeepSeek 版），单模型 `deepseek:deepseek-v4-flash` + 任务难度 → 推理等级（reasoning_effort: low/medium/high）映射，纯文本输入，无模型回退链。
- 实验仓库：`franklil0401/web_learning_tool`（唯一），固定 base commit `c40a5a78bc3e0b549932129713ac65806815c579`。
- 结论适用范围：仅限 web_learning_tool 及同类中小型 Python 仓库、deepseek-v4-flash 能力范围内；不宣称跨语言/跨规模/跨模型结论。

## 2. 评测矩阵

- 任务集：`evoweave_ds_v1`，8 项真实需求（bench-01 ~ bench-08），覆盖单文件/单模块/多模块串行/多模块并行场景。
- Agent 策略（3）：`single_agent`、`fixed_multi_agent`、`adaptive_agent`。
- 推理等级策略（3）：`fixed_low`、`fixed_high`、`adaptive_model`（按任务难度动态调整）。
- 重复次数：每任务 × 每策略组合 2 次（trial 1、trial 2）。
- 总运行数：8 × 3 × 3 × 2 = 144 条 `live_model` 记录。

## 3. 运行环境

- 模型：DeepSeek OpenAI 兼容网关，base URL `https://api.deepseek.com`，模型 `deepseek-v4-flash`。
- 参数：温度恒为 0；`reasoning_effort` 为唯一允许变化的模型参数。
- API Key：从环境变量 `Deepseek_api_key` 读取（Machine 级），不进入任何结果文件。
- 运行上限（每 Worker）：max_steps=32、max_input_tokens=1,000,000、max_output_tokens=16,384、max_total_output_tokens=262,144、max_tool_calls=32、timeout=900s。
- 本地执行：宿主机受限执行（allow_host_execution=True），写任务使用独立 Git worktree，实验分支命名 `evoweave-exp/*`（基准分支）/ `evoweave_ds/run_*/task_*`（矩阵运行分支）。

## 4. 复现命令

```powershell
# 需求集校验
uv run evoweave_ds benchmark validate --suite benchmarks/任务集/真实仓库需求集.json

# 规划审计（不调用模型）
uv run evoweave_ds benchmark audit --suite benchmarks/任务集/真实仓库需求集.json --output benchmarks/结果

# 正式运行：9 组 × 8 需求 × 2 重复（已有记录自动跳过）
uv run evoweave_ds benchmark run --suite benchmarks/任务集/真实仓库需求集.json --results benchmarks/结果/真实模型结果.json --all-strategies --trials 2 --provider deepseek

# 汇总（缺失组合保持 PENDING）
uv run evoweave_ds benchmark summarize --suite benchmarks/任务集/真实仓库需求集.json --results benchmarks/结果/真实模型结果.json --output benchmarks/结果
```

## 5. 判定规则（预注册，见实验方案.md 第 8 节）

- **门槛 A（整体效率）**：实验组（adaptive_agent × adaptive_model）成功率 ≥ 最佳基线 − 5pp，且平均 Token 或平均时延 ≤ 最佳基线 × 80%。
- **门槛 B（复杂需求收益）**：high 难度任务子集上成功率 ≥ 最佳基线 + 15pp（任务集无 high 难度任务时如实记录"不适用"）。
- **C1 最小实例**：low 难度任务上实验组平均 Agent 数 ≤ 1.2。
- **C2 上下文隔离**：调度上下文压缩比 ≤ 0.5。
- **C3 推理等级匹配**：动态组难度预测与规则评估匹配率 ≥ 90%。
- **C4 无静默换模型**：全部运行模型恒为 `deepseek-v4-flash` 且无回退记录。
- **C5 分支纪律**：运行不写 main、实验分支补丁可应用且证据完整。
- **C6 数据诚实**：无删除失败样本、无补零、完整矩阵（9 组 × 8 需求 × 2 重复）。
- 结论：全部满足 → GO；任一不满足 → NO_GO；矩阵不完整 → PENDING。

## 6. 统计检验（汇总报告内）

- 成功率差异：单尾 Fisher 精确检验（实验组 vs 每个基线组）。
- Token / 时延分布差异：双尾 Mann-Whitney U 检验。
- 显著性阈值：p < 0.05。
- 实现：`src/evoweave_ds/benchmarking/statistics.py`（纯 Python，无 scipy 依赖）。

## 7. 成本与数据说明

- 真实 API 调用按次计费；每条运行消耗 Token 量见结果记录的 input/output/reasoning_tokens 字段。
- 运行证据（补丁、验证报告、事件日志、检查点）保存在 `benchmarks/结果/运行证据/<run_id>/`。
- 失败样本保留并分类（协议失败 / 运行上限 / 验收未通过 / 回归 / 模型失败 / 基础设施 / 需求不可达），不删除、不补零。
- 已知观察：多 Agent 场景（adaptive 拆分为 2 个 Worker）对话历史无缓存命中时，累积输入容易逼近 1M 上限（bench-04 曾触发运行上限）；模型生成代码偶发违反 Ruff E731 等 lint 规则被验证门拦截（bench-07）。

## 8. 防作弊规则（与实验方案.md 第 9 节一致）

1. 三种 Agent 策略使用同一 base commit、同一允许/禁止路径、同一运行上限、同一需求验收；
2. 温度恒为 0；`reasoning_effort` 为唯一允许变化的模型参数；
3. 需求验收与全量回归同时通过才算成功；
4. 补丁越权、未应用或未授权不记为通过；
5. 失败运行必须保留结构化原因与证据；
6. 同一报告中的记录必须绑定同一 base commit SHA、同一任务集摘要与同一系统 Git commit；
7. 模型失败场景要求注入一次首选模型不可用故障验证（后续补充）；
8. API Key 值、完整私有推理和未脱敏源码不得进入结果文件；
9. 每项隐藏验收必须证明基线失败、正确实现通过；
10. 探索性运行与正式运行分离；
11. 实验分支与 main 隔离：运行前后 main HEAD 不变（以 SHA 校验）。
